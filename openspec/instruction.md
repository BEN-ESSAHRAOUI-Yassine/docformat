# OpenCode Instructions

## Stuck / Long Thinking Recovery

If you appear to be stuck, thinking for an unusually long time, repeating the same reasoning, or making no meaningful progress:

1. Do not keep thinking indefinitely.
2. Review the last action, tool result, or change you made.
3. Identify what is blocking progress.
4. If a command or tool appears to be hanging, stop waiting for it and use an alternative approach.
5. Continue from the current state instead of restarting the task.
6. Prefer making a reasonable decision over repeatedly considering multiple possibilities.
7. If something is genuinely blocking you, briefly explain the blocker.
8. If you need to make an assumption, make the safest reasonable assumption and continue.
9. Only ask the user when their answer is genuinely required.
10. Never remain idle indefinitely. If progress is possible, take the next concrete action.

Recovery flow:

**inspect current state → identify blocker → take action → verify → continue**

## Avoid Overthinking

Do not spend excessive time analyzing a problem that can be solved by inspecting the code and testing the obvious solution.

For coding tasks:

- Inspect only relevant files.
- Make the smallest appropriate change.
- Run a focused check or test.
- Fix resulting errors.
- Continue.

Do not repeatedly reconsider an approach when there is enough evidence to proceed.

## General Execution Rule

Always favor concrete progress over prolonged analysis.

If the current approach is not working, change the approach rather than continuing to wait or reason indefinitely.

## Tool Usage

Do not repeatedly run the same command or inspect the same files without a new reason.

If a command produces no result or appears to hang:

- Do not wait indefinitely.
- Stop it when appropriate.
- Diagnose the likely cause.
- Try a focused alternative.

After each tool call, use its result to decide the next concrete action.
